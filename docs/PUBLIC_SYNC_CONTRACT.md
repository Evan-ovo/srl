# Public 同步核验约定

Public 的共享功能来自维护者授权的主库快照。日常先完成主库检查和提交再同步；明确授权整轮对齐时可以包含经核对的当前共享工作区修改。未经授权的开发分支不进入同步。主库的私有提交 SHA 只记录在主库既有工作记录中；Public 记录对应版本与自身审计基线。

代码使用 `SRL-PUBLIC-SYNC` 标记：`MAIN-ONLY` 排除账号及官方托管服务，`REPLACE` 保留两端同 ID 的必要替代实现，`WORKER-URL` 保留用户配置的服务地址，`PUBLIC-ONLY` 标注 Public 独有适配。标记范围须按真实依赖核查，不能仅因名称包含 `OfficialApp` 或“助手”而排除共享功能。

内置 APP 管理、安装、更新、卸载、内容修订号、加载门及打包代码使用当前站点的静态包，属于共享功能，不按 `OfficialApp` 名称排除。已有安装支持校验清单、复用未变化文件和按需补齐依赖；同内容版本的依赖变化沿共享兼容修复流程处理。第三方 APP 保持完整 `.srlapp` 包导入/更新和整包校验。账号服务、资源广场、公告、反馈、官方共享托管与官方 APK 更新通道继续排除；APP 内容更新与 APK 更新是不同能力。

同步后应覆盖所有共享源码、样式、读了么 HTML/脚本、运行时、APP 打包配置和相关测试。逐项核查保留替换区内的上游变化；特别是 Worker 地址适配不能保留整段旧业务实现。复核主库中尚未完整标记的账号绑定、广场 ID 等代码，避免残留导入和入口。

Public 不提供官版内置的公共中继，也不设默认中继地址。`RelayWorkerSettingsService` 统一管理自部署 Worker 的地址存储、校验、检查结果与活动操作，保留既有 Public 存储键；重复的旧设置 Service 与未引用教程已移除。未填写自部署地址时，Koofr 中转、设备码和加密暂存不可用；网页 GitHub 默认直连，配置后只经自己的 Worker。设备码仍要求检查通过，Discord Bridge 继续使用独立设置。

所有内置 APP 均通过 `FeatureAppLoaders` → `OfficialAppGate` → `OfficialAppRuntime` 加载，网页与包内 UI 入口由 `OfficialAppPackages` 维护。`FeatureAppLoaders.test.ts` 检查全部 APP 使用同一加载链，并核查前端了么、缝了么和助手的实际打包入口。同步后运行相关回归、类型检查、构建与包完整性检查；真机和线上验收单独记录。

品牌、图标、应用 ID、签名与部署地址保持 Public 身份。公开前按 README 执行增量隐私和提交邮箱检查；同步本身不推送、部署或构建 APK。

维护者同步器应用前核查全部计划差异，应用后审计实际源码。单独审计不使用未落盘的同步计划；替换区的上游实现变化必须复核，不能以标记隐藏漏同步的普通业务。主库确认说明和 Owner 后，助手知识清单按 Public 实际存在的共享 Owner 投影。使用者正常更新自己的 Fork 并重新构建部署即可获取已发布的 Public 更新，无需手动合并主库私有代码。

“0 差异”表示排除账号代码、保留明确替换区后的源码投影一致，不代表替换区内部逐字相同。完整对齐还需复核替换区中的普通业务和对应回归，不能只看审计计数。当前脚本未覆盖 HTML 模板；应额外检查 `src/templates/`，仅保留私人图片地址的占位替换及不改变行为的格式差异。

共享依赖与锁文件随功能更新，账号服务器的 workspace 不进入 Public。版本号随共享发布基线更新，Public 的 buildId、发行修订、Android 应用身份和签名保持独立。同步维护者当前工作区前须排除未经验证的并行施工；同步成功不等于已推送或部署。
